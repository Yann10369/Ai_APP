## 一、移动端前端（Android / Flutter）

### 1. 基础架构

## 二、后端（Python FastAPI/Flask）

### 1. 服务基础

| 编号 | 功能 | 实现要点 |
|------|------|----------|
| F-B1 | Web 框架 | FastAPI（异步）+ Uvicorn |
| F-B2 | 配置管理 | 环境变量加载 API Key、清理周期、端口 |
| F-B3 | 日志系统 | Loguru，按天切分日志 |
| F-B4 | 全局异常拦截 | 统一 JSON 错误码：400 / 401 / 413 / 429 / 500 |
| F-B5 | 请求限流 | slowapi 或自研令牌桶，每用户 60 次/分钟 |

### 2. 文件处理模块

| 编号 | 功能 | 实现要点 |
|------|------|----------|
| F-F1 | 文件上传 | multipart/form-data，字段：image、mask |
| F-F2 | 大小校验 | 单文件 ≤ 10MB，超限返回 413 |
| F-F3 | 类型校验 | 仅接受 PNG/JPG/WEBP |
| F-F4 | 像素对齐 | 校验 mask 与原图分辨率一致，否则自动 resize |
| F-F5 | 临时文件命名 | UUID + 时间戳命名，避免冲突 |

### 3. AI 调用模块

| 编号 | 功能 | 实现要点 |
|------|------|----------|
| F-AI1 | 修复接口调用 | 同步封装 LaMa/SD-Inpainting API |
| F-AI2 | Prompt 模板 | 根据场景（人物/宠物/杂物）选择不同 Prompt |
| F-AI3 | 超时处理 | 单次调用 ≤ 60s，超时返回 504 |
| F-AI4 | 重试机制 | 指数退避重试 2 次，失败抛错 |

### 4. 缓存与去重

| 编号 | 功能 | 实现要点 |
|------|------|----------|
| F-C1 | 内容哈希 | 对 (image + mask) 做 SHA256，相同请求命中缓存 |
| F-C2 | 缓存存储 | Redis 或本地磁盘缓存，TTL = 24h |
| F-C3 | 缓存淘汰 | LRU 策略，磁盘占用上限 2GB |

### 5. 异步任务

| 编号 | 功能 | 实现要点 |
|------|------|----------|
| F-Q1 | 异步任务 | Celery + Redis 队列处理修复请求 |
| F-Q2 | 任务进度 | 客户端轮询 `/api/task/{id}` 状态 |
| F-Q3 | 任务取消 | 支持中途取消，清理临时文件 |

### 6. 隐私与清理（重点）

| 编号 | 功能 | 实现要点 |
|------|------|----------|
| F-P1 | 临时目录 | `/tmp/eraser/` 集中存放上传图片与修复结果 |
| F-P2 | 定时清理 | 启动 APScheduler，每 30 分钟清理 1h 前文件 |
| F-P3 | 启动清理 | 服务启动时强制清空残留临时目录 |
| F-P4 | 不持久化 | 数据库不存任何用户原图与蒙版 |
| F-P5 | 密钥安全 | API Key 走环境变量，前端绝不接触 |

## 三、AI 模型模块

### 1. 模型选型

| 编号 | 功能 | 实现要点 |
|------|------|----------|
| F-M1 | 主方案 | LaMa（Large Mask Inpainting）端侧部署 |
| F-M2 | 备选方案 | Stable Diffusion Inpainting（云端 API） |
| F-M3 | 备选 B | 豆包/千问 多模态图像编辑 API |
| F-M4 | 模型切换 | 配置项 `MODEL_BACKEND=lama/sd/doubao` |

### 2. 端侧部署（LaMa 方案）

| 编号 | 功能 | 实现要点 |
|------|------|----------|
| F-D1 | ONNX Runtime | 加载 LaMa.onnx 模型，GPU/CPU 推理 |
| F-D2 | 输入预处理 | 归一化、padding 到 512×512 |
| F-D3 | 推理 | 单次 ≤ 3s（GPU）/ ≤ 8s（CPU） |
| F-D4 | 输出后处理 | 反归一化、与原图 alpha 混合 |

### 3. 云端 API 方案（SD/Doubao）

| 编号 | 功能 | 实现要点 |
|------|------|----------|
| F-D5 | 客户端上传 | 原图+蒙版 base64 上传 |
| F-D6 | Prompt 模板库 | 按场景分类：人物、宠物、文字、杂物 |
| F-D7 | Prompt 拼接 | "Remove the masked object and naturally fill in the background texture" |
| F-D8 | 结果下载 | 解析返回的图片 URL，下载转字节流返回前端 |

### 4. Prompt 模板库

| 场景 | Prompt |
|------|--------|
| 人物擦除 | `Remove the masked person. Fill the area with surrounding scene, maintain consistent lighting and shadows.` |
| 宠物擦除 | `Remove the masked pet/animal. Reconstruct the ground/grass/floor texture seamlessly.` |
| 杂物擦除 | `Remove the masked object. Maintain original perspective and color consistency.` |
| 文字擦除 | `Remove the masked text. Keep the background texture intact, no artifacts.` |
| 水印擦除 | `Remove the masked watermark. Preserve image quality, fill with natural background.` |

### 5. 调优与测试

| 编号 | 功能 | 实现要点 |

## 四、端到端关键流程

### 流程 1：擦除主流程
```
用户选图 → 进入涂抹界面 → 画笔涂抹目标区域
  → 点击"擦除"按钮 → 上传 (image + mask) 到 /api/erase
  → 后端校验、对齐、调用 AI 修复
  → 流式/异步返回修复图 → 客户端 Before/After 对比
  → 用户满意 → 一键保存到相册 + 写入历史记录
```

### 流程 2：缓存命中
```
相同 (image_hash, mask_hash) 请求到达
  → Redis 命中 → 直接返回缓存结果，耗时 < 200ms
```

### 流程 3：局部重涂
```
用户对修复结果不满意 → 选择"局部修复"
  → 蒙版编辑器预加载历史原图
  → 在已修复图上新增涂抹 → 再次调用 /api/erase
```

### 流程 4：隐私清理
```
定时任务每 30 分钟扫描 /tmp/eraser/
  → 删除 > 1h 的文件
  → 服务重启时强制清空全部
  → 数据库无任何原图/蒙版数据持久化
